# IOLITE — دليل التشغيل الحيّ (أول هدف)  ·  Live Runbook

> **القاعدة الأولى:** لا تُرسل حزمةً واحدة قبل أن تُظهر `iolite live` كلمة **GO** خضراء بالكامل.
> كل خطوة **بشرية ومُبوَّبة**؛ الأداة لا تُطلق شيئاً من نفسها. الفشل دائماً **آمن** (يقف، لا يُخاطر).

هذا الدليل يعبر **فجوة النقل الثلاثية** (النقطة 5): **الأمان** (preflight)، **السلامة** (معايرة اللاحتمية تحمي «صفر إنذار كاذب»)، و**القدرة** (حاكم يتراجع، لا يُراوغ). كلّه **بحساباتك، داخل النطاق، غير مُتلِف، مُصدَّق**.

---

## 0) قبل أي شيء — الأساس القانوني (لا يُختصَر)
- اختر برنامجاً يدفع **كريبتو** ويسمح باختبار API بحساباتك.
- افتح صفحة النطاق (scope). **النطاق يحكم كل شيء.**
- `iolite research --live --scaffold <handle>` → يولّد `engagement.json`.
- افتح الملف، واكتب **بيدك**:
  - `authorized_by`: رابط النطاق العام.
  - `in_scope_hosts` / `out_of_scope_hosts`: من الصفحة بالضبط.
  - `attestation`: جملةٌ **تكتبها أنت** تؤكّد أنك مُصرَّح وأن كل الحسابات لك.
- التصديق **فعل قانونيّ واعٍ** — الأداة لن تُصدّق نيابةً عنك، وترفض الحيّ بدونه.

## 1) حسابان لك
أنشئ **حسابين حقيقيين مِلكك** (A و B) على الهدف. تحتاج اثنين لأن إثبات التفويض عبر‑المبدأ يقارن «ما يراه A» بـ«ما يجب ألّا يراه B». **لا تستخدم حساب أحدٍ آخر أبداً.**

## 2) الالتقاط (سلبيّ، مناع للتعتيم)
- افتح المتصفّح، سجّل دخول كـ **A**، افتح DevTools → Console.
- الصق محتوى `iolite/assets/iolite_surface_hook.js` واضغط Enter → «hook armed».
- **استعمل التطبيق بشكل طبيعي** (طلباتك، صفحاتك، إعداداتك). العميل يبني ويرسل طلباته الحقيقية وأنت تسجّلها.
- شغّل `__IOLITE_dump()` → ينزل `iolite-runtime.json`. سمِّه `A.runtime.json`.
- كرّر كـ **B** → `B.runtime.json`. صدّر أيضاً HAR لكلٍّ إن أمكن.
- ضع كل الملفات (HAR / JS / runtime / engagement.json) في مجلّد واحد `./captures`.

## 3) معايرة اللاحتمية (تحمي صفر‑الإنذار — لا تتخطّاها)
الهدف الحيّ **يتغيّر بين قراءتين** (طوابع، عدّادات…). لو أكّد ONYX على «تغيّرٍ» ليس خرقاً = تقرير كاذب = انهيار قيمتك.
- اقرأ **كائناً واحداً تملكه** (طلبك أنت مثلاً) **٥ مرّات** متتالية، واحفظ الأجسام في `samples.json` (مصفوفة JSON).
- `iolite live --dir ./captures --samples samples.json`
- سيطبع **الحقول المتقلّبة** و`stability_k` والقيم التي **تضبطها على ONYX** قبل الفحص الحيّ. اضبطها.

## 4) التفكير أوفلاين (بلا حزم — كل قوّتك هنا)
```
iolite reason --dir ./captures --sequence --deep --rich-intent --readiness --kb prog_kb.json --writeup findings/
```
- `--sequence` (نقطة1): تخطّي‑بوابة/انتقال. `--deep` (نقطة2): سطح عميق. `--rich-intent` (نقطة3): نيّة أذكى. `--readiness` (نقطة4): بوّابة GO/HOLD/DROP. `--kb`: يرصد **انحدار الحُرّاس** (ثغرة طازجة!).
- راجع `findings/` والـreadiness. **قدّم لاحقاً فقط ما وسمه GO.**

## 5) بوّابة الأمان — preflight (فاشلٌ‑مغلقاً)
```
iolite live --dir ./captures
```
- إن ظهر **أي ✗** (تصديق/نطاق/حسابان/غير‑مُتلِف/حاكم/ONYX) → **قف وأصلحه.** لا حيّ حتى يصير كله ✓.
- إن ظهر **GO** و`live-ready: True` → تابع.

## 6) الإثبات الحيّ (ONYX يؤكّد بالΔstate تحت attestation)
> افعلها فقط بعد GO أخضر + معايرة مضبوطة. ابدأ بـ **مرشّح GO واحد** عالي القيمة، لا مسحاً.
```
ONYX_PATH=/path/to/onyx iolite reason --dir ./captures --cegar --depth 3 --keep-tokens --writeup findings/
```
- الحاكم **يتراجع** عند 429/WAF (لا يُراوغ). لو انحجبت — توقّف، أبطئ، أعد لاحقاً.
- **الطفرة تبقى بقرارك**: الافتراضي كبحٌ تام؛ الكتابة الواحدة المُفضَّلة‑الرجوع على كائنك تحتاج `--allow-write` + `allow_destructive` + تصديق.
- ONYX يؤكّد فقط Δstate **يتجاوز أرضية الضجيج المُعايَرة** على حقلٍ أمنيّ — وإلّا **يمتنع** (صدق).

## 7) التقديم والإدارة بالأرقام
- قدّم على المنصّة **فقط** التقارير المؤكَّدة‑من‑ONYX والموسومة GO. أرفق دليل الΔstate من `findings/`.
- سجّل كل نتيجة:
```
iolite econ --file econ.json --add --program <p> --status paid|duplicate|informational --payout N --hours H
iolite econ --file econ.json         # $/ساعة محقّقة + FOCUS/ROTATE/DROP
```

---

## السقف الصادق (لا وهم)
- **البوّابات تضمن أن التشغيل سليمٌ وآمن — لا أنه يدفع.** التكرار وحظّ السوق خارج سيطرتك (نقطة4 تديرهما إحصائياً).
- **أول أسابيع تعلّمٌ قد تكون $0.** الأداة **شرط دخولٍ قويّ، لا ضمان.**
- **فاشلٌ‑مغلقاً دائماً:** لا شيء أأمن من عدم إرسال حزمةٍ سيّئة.
- **ضمن قواعد الاشتباك، لا مراوغة.** احترم النطاق وحدود المعدّل وToS الهدف حرفياً.

**تسلسل الأوامر باختصار:** research → (حرّر engagement.json) → التقاط بالخطّاف → `live --samples` (معايرة) → `reason … GO` → `live` (preflight=GO) → `reason --cegar` (حيّ) → تقديم GO → `econ`.
